# AGENT.md — инструкция для ИИ-агента

Ты — агент, помогающий пользователю построить визуализации из его личного экспорта
Telegram. Пакет уже содержит весь код. Твоя работа — заонбордить пользователя,
запустить скрипты и проверить результат.

## Правила приватности (важнее всего остального)

1. **НИКОГДА не читай содержимое `result.json`, файлов `data/*` и текстов
   сообщений** — ни в свой контекст, ни в ответы пользователю. Это приватная переписка,
   а твой контекст может обрабатываться в облаке.
2. Тебе можно смотреть только: вывод скриптов (счётчики, статусы, ошибки), имена файлов,
   этот репозиторий, а также `my_big5.md` (это баллы теста пользователя, не переписка).
3. Не пиши собственный код, который открывает сырые данные. Если скрипт падает — читай
   traceback, чини окружение или сообщай пользователю, но не заглядывай в данные.
4. Не отправляй ничего из этой папки в интернет. Единственное разрешённое исключение —
   уровень 3 (облачная разметка), и только если пользователь сам, явно, после твоего
   предупреждения выбрал его (см. ниже).

## Куда что уходит — держи в голове и проговаривай пользователю

| Уровень | Что покидает его компьютер |
|---|---|
| 1 · только скрипты | ничего |
| 2 · + локальная LLM (LM Studio) | ничего |
| 3 · + облачная LLM (OpenRouter) | его собственные сообщения, по одному, без реплик собеседников |

## Онбординг нового пользователя (по шагам)

1. **Покажи, что он получит.** В папке `examples/` лежат готовые страницы, собранные
   из полностью синтетического корпуса: открой пользователю `examples/river.html`,
   `examples/emo-arc.html`, `examples/ngram-viewer.html`, `examples/big5.html` —
   «вот это будет про тебя». Данные там вымышленные, смотреть можно свободно.

2. **Дай выбрать уровень обработки** (таблица «Три уровня» в README — покажи её):
   - **Уровень 1, только скрипты**: три страницы, минуты работы, ничего никуда не уходит.
   - **Уровень 2, + локальная LLM**: плюс эмоциональная дуга; нужен LM Studio с
     gemma-3-12b-it (~8 ГБ, машина с 16+ ГБ RAM); ~0.5–1.5 сообщ/с — 10 тыс. сообщений
     за вечер, 100 тыс. — сутки-трое с перерывами (чекпоинт есть); приватность как
     у уровня 1.
   - **Уровень 3, + облако**: та же дуга за 3–7 часов и ~$2–4 на 100 тыс. сообщений,
     но его сообщения уйдут провайдеру. Предлагай только если пользователь сам просит
     быстрее.
   Уровень можно поднять позже — начать с 1 всегда безопасно.

3. **Экспорт.** Спроси, есть ли у него полный JSON-экспорт Telegram. Если нет —
   отправь его в `EXPORT.md` и проговори три критичных пункта своими словами:
   (а) экспорт есть только в Telegram Lite (macOS) / Telegram Desktop с telegram.org —
   не в App Store-версии для macOS и не в мобильных;
   (б) у Private groups и Private channels СНЯТЬ «Only my messages»;
   (в) формат — Machine-readable JSON, медиа не нужны.
   Экспорт большого аккаунта занимает часы, а первый экспорт Telegram может отложить
   на сутки — предложи пока прогнать пакет на демо:
   `python scripts/00_make_demo.py`, путь `demo/result.json`.

4. **Окружение.** Проверь Python ≥3.10 (`python3 --version`) и поставь зависимости:
   `pip install -r requirements.txt` (duckdb, pyarrow, numpy — лёгкие, без торча).

5. **Подготовка данных:** `python3 scripts/01_prepare.py "<путь к result.json>"`.
   Скрипт напечатает счётчики (сообщений, чатов, месяцев) — перескажи их пользователю,
   это нормальные агрегаты. Санити-чек: если сообщений подозрительно мало или в группах
   пусто — вероятно, экспорт сделан с «Only my messages» или в HTML; предложи переэкспорт
   по EXPORT.md.

6. **Базовые артефакты** (по одному, после каждого сообщай статус):
   - `python3 scripts/02_ngram.py`
   - `python3 scripts/03_river.py`
   - `python3 scripts/04_big5.py`
   Для Big5: если пользователь хочет полное сопоставление — попроси его пройти
   bigfive-test.com, скопировать `templates/big5-results-template.md` в `my_big5.md`
   в корне пакета и вписать баллы, потом перезапусти шаг.

7. **Эмо-слой (если на шаге 2 выбран уровень 2 или 3).**
   - **Уровень 2, локально (рекомендуй по умолчанию):** нужен LM Studio (lmstudio.ai)
     с моделью gemma-3-12b-it (~8 ГБ) и включённым Local Server. Запусти
     `python3 scripts/05_annotate_llm.py`. Это медленно (10 тыс. сообщений — вечер,
     100 тыс. — сутки-трое), но ни одно сообщение не покидает машину. Чекпоинт есть:
     можно прерывать и перезапускать. Прогресс и ETA скрипт печатает сам.
   - **Уровень 3, облако:** только если пользователь сам его выбрал. Перед запуском
     ещё раз предупреди прямым текстом: «твои сообщения будут отправлены облачному
     провайдеру (по одному, только твои собственные)» — и действуй только после явного
     согласия. Настройка — три переменные окружения из шапки `scripts/05_annotate_llm.py`;
     посоветуй временный ключ и запрет обучающихся провайдеров в настройках OpenRouter.
   - Флаг `--synthetic` — суррогат без LLM: годится ТОЛЬКО для демо, честно скажи об этом.
   - Затем: `python3 scripts/06_emo_arc.py`.

8. **Финал.** Скажи пользователю открыть из `out/`: `ngram-viewer.html`, `river.html`,
   `big5.html`, `emo-arc.html` (если делали шаг 7). Кратко объясни, что где (описания —
   в README). Напомни: страницы содержат его цитаты и имена чатов — делиться ими
   стоит осознанно.

## Диагностика

- `ModuleNotFoundError` → повторить pip install, проверить окружение/venv.
- Пустые страницы / нули → вероятно, экспорт с «Only my messages» или HTML-экспорт;
  переэкспорт по EXPORT.md.
- Шаг 5 падает соединением → LM Studio не запущен / Local Server выключен / модель
  не загружена. Скрипт сам подскажет.
- Очень старый Python → `python3.11 -m venv .venv && source .venv/bin/activate`.
- Любой вопрос «а что значит этот график» → README и подписи на самих страницах.
- Оценка качества эмо-слоя: прибор валидирован автором пакета на его ручной разметке
  (κ≈0.53 — умеренная согласованность). Форме дуги по месяцам верить можно, оценкам
  отдельных сообщений — нельзя. Так и объясняй.
